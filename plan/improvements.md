# Improvements & deferred ideas

One line per entry, most recent first.

- ImageZoom.showLightbox's close button click handler needed event.stopPropagation() to prevent bubbling to the overlay's click handler and calling closeLightbox twice; fixed in phase 6 to pass tests.
- jsdom has no `document.fonts`, so `collectReadinessSignals`' web-font signal (`dev/js/animation/animBarba.mjs:88-90`) is skipped in every test — the only readiness branch the phase-1 suite cannot exercise; stub a FontFaceSet if that branch ever grows logic.
- `EventEmitter.resolveNames` turns a comma *followed by a space* (`on('a, b', cb)`) into an empty-string event name, registering a phantom listener under `callbacks.base['']` — harmless today because no caller uses that spacing; collapse repeated separators when phase 2 touches the emitter.
- `Resources.loadSource()` passes no onError callback to any of the three loaders (`dev/js/three/utils/Resources.mjs:192-223`), so one failed non-moodboard source never increments `loaded` and `resourcesReady` never fires at all — a silent stuck world; candidate for phase 3.
- In progressive mode `checkOverallLoadCompletion()` only runs for the *last* texture of a batch, so if the overall tally completes on a non-final texture `resourcesReady` is skipped entirely (`dev/js/three/utils/Resources.mjs:283-320`) — narrow but real; consider calling it per source in phase 3.
- A failed moodboard texture still increments `Resources.loaded` (`dev/js/three/utils/Resources.mjs:327`), so `loaded === toLoad` — and therefore `resourcesReady` — can fire with items missing from `this.items`; pinned as current behaviour in `tests/js/three/utils/Resources.test.mjs`.
- `header.php`'s `<title>`, `section-headline.php`'s `data-value` and every `getResponsiveImage()` alt built from `$page->title()` show project titles' `<mark>` as literal `&lt;mark&gt;` text (browser tab, alt text) — pre-existing, left byte-identical by phase 6; add a plain-text title method (strip_tags then esc) for attribute/`<title>` contexts.
- Kirby only lists folders with a `<num>_` prefix, so live project folders like `01-phenotype-agency` are unlisted and `projects.php`'s `children()->listed()` list renders only `berlin_im_wandel_der_zeiten` (num "berlin") — found by phase 6; renaming content folders is a human content call (and changes URLs).
- `tests/php/OutputEscapingGuardTest.php` only scans `<?=` tags; `<?php echo` output (header.php's slug class, section-headline.php's title chunks) is not guarded — extend the scanner to T_ECHO if more echo-statement output appears.
- `app/site/snippets/tag-list.php` (related-grid) and `create_tags()` (helpers plugin, article.php) still render tag `<li>`s two ways — both escape since phase 6, but tag-list keeps no-trim/empty-items-kept while create_tags strips spaces and skips empties; unify them in a later pass.
- `app/site/templates/about.php:52-56` still has a commented-out "awards & recognition" block referencing `$page->recognition()`, out of scope for phase 2 (only the OFFICE LOCATIONS block was named) — delete it in a later cleanup pass if `recognition` never ships.
- No live content anywhere under `app/content` uses the `article` template (no `Tags:` field either) — phase 3's `create_tags()` fix is exercised only by `tests/php/plugins/HelpersTest.php` and `scripts/smoke.sh` never renders an article page; if the `article` template ships live content later, add its path to `scripts/smoke.sh`'s `PATHS`.
- `remove_br_tags()` (app/site/plugins/helpers/index.php, moved from snippets/utils.php in phase 3) strips only self-closing `<br/>`/`<br />`, not a bare `<br>` — pinned as current behaviour in HelpersTest; widen the regex if bare tags ever need stripping.
- No page under `app/content` uses the `moodboard` template and no route serves it, so the World_02 moodboard (`dev/js/three/projects/moodboard/`) is unreachable in a browser — phase 3 could verify its batch sequencing only by unit test; add a moodboard page (or a dev-only route) if that world is meant to ship.
- `dev/js/three/projects/moodboard/loaders/BatchLoader.mjs` is a second, independent texture-batch loader that bypasses the `Resources` batchLoaded/batchProcessed handshake entirely, and `ProgressiveLoader` drives both paths — phase 3 left it alone (it does not implement the handshake it would have had to reuse); unify the two loading strategies in a later pass.
- Phase 3 deleted the per-texture `console.log` tracing in `Resources.startBatchLoading` (duplicated across the two copied completion blocks) to get the file under the 300-line threshold — if that tracing is wanted again it should return behind a debug flag, not as unconditional logging.
- Phase 4 left `Experience` with fan-in 9 (scan threshold 8: every world/util imports it for the singleton) — the only remaining hotspot on it; passing the Experience to consumers instead of `new Experience()` in each would clear it but changes every module's constructor.
- `runExperience.js` still logs `'runExperience in ...'` unconditionally — no world-name validation happens before `new Experience`; the registry now reports unknown names, but the caller only learns via console. (SEC-02 fixed in phase 6: window.experience now gated to DEV.)
